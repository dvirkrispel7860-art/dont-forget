# Don't Forget

> אל תצא בלי מה שאתה צריך.

אפליקציה שעוזרת לא לשכוח דברים כשיוצאים מהבית. מגדירים פעם אחת יעדים קבועים
(אימון, בית ספר, ים...) ולכל יעד את הדברים שלוקחים אליו. בפעם הבאה בוחרים את
היעד ועושים **בדיקת יציאה** מהירה.

---

## הפעלה

```bash
cd dont-forget
npm install
```

### על הטלפון (מומלץ)

```bash
npm start
```

התקן **Expo Go** מ‑Google Play / App Store, וסרוק את ה‑QR שמופיע בטרמינל.
האפליקציה תיפתח על המכשיר האמיתי, כולל שמירה מקומית של הנתונים.

### בדפדפן (הכי מהיר לבדיקה)

```bash
npm run web
```

ואז לפתוח http://localhost:8081 (כדאי להקטין לרוחב של טלפון בכלי הפיתוח).

### בילדים מקומיים

```bash
npm run android
npm run ios
```

### כ‑PWA (התקנה בטלפון בלי חנות אפליקציות)

```bash
npm run build:web
npm run serve:web
```

הראשון בונה ל‑`dist/`, השני מגיש אותו על http://localhost:4173.
להתקנה אמיתית צריך **HTTPS** (localhost פטור) — פרטים בהמשך.

> ה‑Service Worker נרשם רק בבילד המיוצר, לא בשרת הפיתוח. הזיהוי הוא לפי קיום
> סקריפט תחת `/_expo/static/js/web/`, שקיים רק ב‑export. כך `npm start` לא סובל
> מ‑caching שנלחם ב‑hot reload.

## מסכים

### סרגל ניווט תחתון

שלוש כרטיסיות, מסודרות משמאל לימין: **🕘 היסטוריה · 🏠 בית · ➕ הוסף יעד** —
"בית" ממורכז ו"הוסף יעד" בקצה הימני. ההגדרות אינן כרטיסייה אלא כפתור **⚙️**
בפינה השמאלית העליונה של כל מסך כרטיסייה.

| מסך | קובץ | מה קורה בו |
| --- | --- | --- |
| פתיחה | `app/index.tsx` | לוגו, סלוגן, כפתור **התחל** |
| בית | `app/(tabs)/home.tsx` | "לאן יוצאים היום?" – אזור "היעדים שלי", **מועדפים ראשונים**, **🧠 אזור AI** (עם 🎙️ הכתבה) מעל סרגל הניווט, ומסך ריק עם **הוסף יעד ראשון**. הוספת יעד היא הכרטיסייה שבסרגל |
| הוסף יעד | `app/(tabs)/new.tsx` | שם + כתובת לניווט + אייקון, עם תצוגה מקדימה חיה |
| היסטוריה | `app/(tabs)/history.tsx` | יציאות קודמות: שם יעד, תאריך, שעה, `6/6 פריטים ✓`. מסך ריק כשאין |
| פרטי יציאה | `app/trip/[id].tsx` | תאריך ושעה + כל הפריטים, מחולקים ל"נלקחו" ו"לא נלקחו" |
| הגדרות | `app/settings.tsx` | שם משתמש, התראות, הגדרות ניווט, מחיקת כל הנתונים באישור |
| פריטים | `app/destination/[id]/items.tsx` | "מה אתה צריך לקחת?" – הוספה ומחיקה, עריכת הכתובת, **שמור יעד** |
| בדיקת יציאה | `app/destination/[id]/check.tsx` | **המסך היחיד של היציאה** — התקדמות, סימון פריטים, **🌦️ מזג האוויר** + הצעות + **📍 בחר מיקום**, **🚦 איך מגיעים?**, **🚌/🚗 הדרך שלי** (באוטובוס: התחנה שנמצאה עבורך + זמן אמת), **🔔 תזכורת**, **🧠 הצעות חכמות**, **נווט ליעד 🗺️**, וכפתור אחד: **✅ מוכן לצאת** |
| תוכנית יציאה | `app/plan.tsx` | **🧠 תוכנית היציאה שלך** — יעד, זמן שזוהה מהמשפט, רשימה + המלצות, מזג אוויר לשעה המתוכננת, הדרך (כולל זמן אמת), ניווט, תזכורת, ו‑**🚀 התחל יציאה** |

הכרטיסיות נשארות טעונות, כך שמעבר ביניהן לא מאבד מידע — טיוטה שהתחלת להקליד
במסך "הוסף יעד" תמתין לך בחזרה. מסכי הפריטים, בדיקת היציאה וההגדרות נפתחים
מעל הסרגל (stack), ולכן הסרגל מוסתר בהם.

לחיצה על ✎ בכרטיס יעד פותחת שוב את מסך הפריטים לעריכה (ומשם גם ניתן למחוק את היעד).
לחיצה על ☆ מסמנת יעד כמועדף — מועדפים עולים לראש מסך הבית.

הנתונים מפוצלים למפתחות נפרדים — `destinations` / `trips` / `settings` /
`active-exits` / `weather` — כדי שתוספות כמו היסטוריה, הגדרות ומזג אוויר לא ייגעו
בנתוני היעדים הקיימים. `weather` הוא cache של מקור חיצוני, לא נתוני משתמש, ולכן
הוא נמצא מחוץ ל‑store — אבל נמחק גם הוא ב"מחק את כל הנתונים".

**טכנולוגיה:** React Native + Expo (SDK 57) + TypeScript.
אותו קוד רץ על Android, iOS ובדפדפן, וניתן להוציא ממנו ילד נייטיב אמיתי דרך EAS.

### תהליך היציאה — מסך אחד, כפתור אחד

```
פתיחת מסך היעד ──[ startExit ]──▶  יציאה פתוחה: מסמנים מה לוקחים
יציאה פתוחה   ──[ ✅ מוכן לצאת → completeExit ]──▶  נשמר בהיסטוריה, חוזרים לבית
```

בדיקת היציאה היא המסך היחיד של היציאה, ואין בו מצבים: פותחים את היעד, מסמנים,
לוחצים **✅ מוכן לצאת**. אין כפתור "אני יוצא" ואין מסך שני — שניהם הוסרו בגלל אותה
תלונה שחזרה שוב ושוב: כל אחד מהם גרם לתחושה של דף נוסף באמצע פעולה אחת.

`startExit` נקרא כשהמסך נפתח (אם אין יציאה פתוחה) — הוא מאפס סימונים שנשארו מביקור
קודם ומסמן את היעד כ"בדרך". `completeExit` שומר תצלום מלא של הרשימה להיסטוריה
(`taken` / `skipped` לכל פריט), מאפס את הסימונים וסוגר את היציאה.

היציאה נשמרת ב‑`dont-forget:active-exits:v1` ולכן נשארת פתוחה גם כשהמסך נסגר:
רענון, מעבר לבית וחזרה, או פתיחה מחדש של האפליקציה — הסימונים במקומם. הדבר היחיד
שסוגר יציאה הוא הכפתור. יעד בלי פריטים לא פותח יציאה בכלל, ואין לו כפתור.

**🚦 איך מגיעים? — בחירה ליציאה הזאת.** אזור בחירה במסך היציאה, עם אותם ארבעה
אמצעים של מסך היעד (`TravelModeSelector` הקיים). ברירת המחדל היא האמצעי ששמור על
היעד, ושינוי כאן משפיע **על היציאה הנוכחית בלבד**: הוא יושב ב‑`DepartureModes`
בזיכרון (כמו הדילוגים), ו‑`startExit` / `completeExit` מנקים אותו. **היעד עצמו לא
משתנה** — לזה יש קישור מפורש אחד, "שמור גם ליעד עצמו", שמופיע רק כשהבחירה שונה
מהשמור וקורא ל‑`updateDestination`.

מה שנגזר מהבחירה: כרטיס הדרך (🚌 → כרטיס התחבורה הציבורית הקיים, אחרת "🚗/🚶/🚲
הדרך שלי"), וכפתור הניווט — Waze לרכב, Google Maps להליכה ואופניים, פרטי נסיעה
לאוטובוס. `navigationAppFor` ו‑`openNavigation` קיבלו פרמטר אופציונלי של אמצעי,
כך שהתנהגות כל הקוראים הקיימים לא השתנתה.

`TripItem` שומר גם `itemId` וגם `name` בכוונה: ה‑id מאפשר בעתיד לקבץ את אותו
פריט על פני יציאות רבות ("את בקבוק המים אתה לוקח ב‑9 מתוך 10 פעמים") גם אם
שינו לו את השם, וה‑name משאיר יציאות ישנות קריאות גם אחרי שהפריט הוסר מהיעד.

`items` אופציונלי בסכימה: רשומות שנכתבו לפני שהתצלום קיים מציגות רק את המספר
שנשמר להן, בלי להמציא להן רשימה.

`favorite` אופציונלי וברירת המחדל שלו כבויה, כך שיעדים קיימים לא משתנים.
מסך הבית ממיין מועדפים ראשונים ב־`byFavoriteFirst()` במיון יציב — הסדר היחסי
בתוך כל קבוצה נשמר.

`address` אופציונלי בסכימה כדי שיעדים שנוצרו לפני שהשדה היה קיים ימשיכו לעבוד —
עבורם הניווט נופל בחזרה לשם היעד. במסך יצירת יעד השדה **חובה**; ביעד קיים אפשר
להוסיף או לתקן אותו במסך העריכה.

`coords` אופציונלי ואינו נכתב על ידי שום מסך היום: שכבת מזג האוויר מעדיפה אותו אם
הוא קיים, ואחרת עושה geocoding לכתובת ושומרת את התוצאה ב‑cache שלה — ולא כותבת
ניחוש לתוך היעד של המשתמש. פיצ'ר עתידי של בחירת נקודה על מפה ימלא אותו, והתחזית
תשתמש בו כמו שהוא.

הכול נשמר ב‑AsyncStorage תחת המפתח `dont-forget:destinations:v1`, ללא חשבון וללא שרת.
כל שינוי נשמר מיד – אין צורך ללחוץ "שמור" כדי שהמידע ישרוד סגירה של האפליקציה.

### "לא צריך הפעם" – שתי התנהגויות שונות

| בחירה | מה קורה | האם נשמר |
| --- | --- | --- |
| **רק הפעם** | הפריט נשאר ביעד, מסומן כמדולג ויוצא מהספירה | לא – חוזר בבדיקה הבאה |
| **הסר מהיעד** | `active = false` | כן – אבל הפריט לא נמחק מהדאטה |

`active: false` היא מחיקה רכה בכוונה: שום דבר שהמשתמש הקליד לא נעלם באמת,
כך שאפשר בעתיד להוסיף "שחזור" בלי מיגרציה.

### ניווט — לפי אמצעי התחבורה

`src/navigation.ts` בוחר את אפליקציית הניווט לפי `travelMode` של היעד ומרחיב את
מה שהיה — `src/waze.ts` עצמו לא נגעתי בו, ולכן נסיעה ברכב עוברת בדיוק באותו מסלול
כמו קודם.

| אמצעי | כפתור | מה נפתח |
| --- | --- | --- |
| 🚗 רכב (וגם יעדים בלי אמצעי) | `🗺️ פתח Waze` | Waze, דרך `openWaze` הקיים |
| 🚶 הליכה | `🗺️ פתח Google Maps` | `dir/?api=1&destination=…&travelmode=walking` |
| 🚲 אופניים | `🗺️ פתח Google Maps` | אותו דבר עם `travelmode=bicycling` |
| 🚌 אוטובוס | `🚌 פרטי נסיעה` | לא נפתחת אפליקציה: המסך גולל לכרטיס **🚌 הדרך שלי** שכבר עליו |

**בטלפון** מנסים קודם את הסכימה של Google Maps (`comgooglemaps://…&directionsmode=…`)
כדי להיכנס ישר לניווט, ואם היא לא נתמכת נופלים ל‑URL האוניברסלי — שממילא פותח את
האפליקציה כשהיא מותקנת, ואת הדפדפן כשלא. **במחשב** נפתח Google Maps בדפדפן.

**איזה מיקום נשלח.** כתובת שהמשתמש הקליד עדיפה על הקואורדינטות השמורות, כי אלה
מגיעות בדרך כלל מ‑geocoding שמדייק לרמת **עיר** — "חוף גורדון, תל אביב" מנווט טוב
יותר מהנקודה שנגזרה ממנו. קואורדינטות מנצחות כשהמשתמש קבע אותן בעצמו ("📍 בחר
מיקום", מסומנות ב‑`coordsLabel`), או כשאין כתובת בכלל. אין אף אחד מהם →
**"לא ניתן לפתוח ניווט כי ליעד אין מיקום"**, ולא נשלח שם היעד כאילו היה כתובת.

**מצב אופניים** נשלח כבקשה ל‑Google Maps; אם אין מסלולי אופניים באזור, Google פותח
את היעד ואומר את זה בעצמו. האפליקציה לא ממציאה מסלול, זמן הגעה או זמינות.


#### Waze (רכב) — כפי שהיה

`src/waze.ts` הוא כל האינטגרציה עם Waze, ולא השתנה. האפליקציה לא מציגה שום נתוני
ניווט בעצמה — היא רק מעבירה את היעד ל‑Waze:

1. בטלפון: קודם `waze://?q=<כתובת>&navigate=yes` — נכנס ישר לניווט אם Waze מותקנת.
2. אם זה נכשל (או בדפדפן, שבו סכימה לא מוכרת נכשלת בשקט): `https://waze.com/ul?q=...&navigate=yes`
   — קישור אוניברסלי שפותח את האפליקציה אם היא מותקנת, ואחרת את Waze Live Map.
3. אם גם זה נכשל: סדין הודעה בעיצוב האפליקציה, בלי נתונים מומצאים.

מה שנשלח ל‑Waze נקבע ב‑`navigationQuery()`: הכתובת אם קיימת, אחרת שם היעד.

### אזור ה‑AI במסך הבית

תיבה קבועה מעל סרגל הניווט: `🧠 מה אתה מתכנן לעשות?` + שדה טקסט + 🎙️ + `שלח`.
שליחה פותחת חלון תוצאה עם פריטים שאפשר לבחור/לבטל, בחירת יעד, ו‑`➕ הוסף לרשימה`.

**אין כאן מודל ואין קריאת רשת.** התשובה מגיעה מ‑`src/aiAnalysis.ts` — התאמת מילות
מפתח מקומית עם סף ביטחון; כשהאיתות חלש מוחזר `understood: false` והחלון אומר במפורש
שלא הובן, במקום לנחש. כשיחובר עוזר אמיתי, מחליפים את `analyzeUserText()` — היא כבר
`async` ומחזירה את אותה צורה — והממשק לא משתנה.

**🎙️ מיקרופון — זיהוי דיבור אמיתי.** `src/speech.ts` עוטף את יכולת ה‑Speech
Recognition של הדפדפן עצמו: `he-IL`, `interimResults` דלוקים ו‑`continuous` כבוי
(משפט אחד בכל פעם). `src/useSpeech.ts` מחבר אותה לתיבה.

הזרימה: לחיצה על 🎙️ → הדפדפן מבקש הרשאת מיקרופון אם צריך → הכפתור עובר למצב פעיל
עם פעימה ו"דבר עכשיו..." → מילות ביניים נכנסות לתיבה בזמן הדיבור → משפט מוגמר נכנס
לתיבה **ומופעל עליו `analyzeUserText` הקיים**, אותה קריאה בדיוק כמו בהקלדה. החוזה של
`analyzeUserText` לא השתנה; הוא רק מקבל את הטקסט מהמיקרופון.

**ביטול** (לחיצה שנייה על 🎙️): ההאזנה נעצרת, מה שזוהה עד עכשיו **נשאר בתיבה**, ולא
מופעל ניתוח — המשתמש מחליט. ההאזנה נעצרת גם ביציאה מהמסך, כדי לא להשאיר מיקרופון פתוח.

**כשאין יכולת:** `isSpeechAvailable()` בודקת בפועל אם קיים מנוע (`SpeechRecognition`
או `webkitSpeechRecognition`), ובנייטיב מחזירה `false` — שם `speechRecognizer` הוא
`null` ולא מדומה שום תמיכה. לחיצה על 🎙️ במכשיר כזה מציגה
`🎙️ זיהוי דיבור לא נתמך במכשיר הזה. אפשר להקליד במקום.` והאפליקציה ממשיכה לעבוד.
חיבור עתידי של פתרון native הוא השמה אחת ל‑`speechRecognizer`.

שגיאות מתורגמות לעברית לפי הקוד שהדפדפן מחזיר: אין הרשאה, לא זוהה דיבור, אין
מיקרופון, אין אינטרנט. `aborted` (המשתמש עצר) לא מייצר הודעה בכלל.

**פרטיות:** האפליקציה לא מקליטה, לא שומרת אודיו ולא שולחת אודיו לשום מקום בעצמה —
היא מקבלת טקסט מהדפדפן. שימו לב שמנוע הדפדפן עצמו עשוי לבצע את התמלול בענן של
היצרן (כך עובד Chrome); זו התנהגות המנוע, לא שלנו, ואותה יכולת בדיוק שכל כפתור
הכתבה באתר אחר משתמש בה.

**כלום לא נשמר בלי בחירה של המשתמש.** ההוספה עוברת דרך `addSuggestedItems`
הקיים, שהוא חסין כפילויות. `סגור` לא כותב כלום.

התיבה גובה ~128px ויושבת בפוטר קבוע; כפתור `+ הוסף יעד` עבר לתוך הגלילה כדי
לפנות לה מקום, כך שהיעדים נשארים גלויים.

### 🧠 כדאי לבדוק

כרטיס אחד לפני היציאה, שמאחד את כל מה שאפשר להציע ביושר. `checkSuggestions`
(ב‑`src/departureContext.ts`) ממזג שלושה מקורות אמיתיים, וכל שורה נושאת את הסיבה
שלה במספרים:

| מקור | דוגמה לשורה |
| --- | --- |
| 🕘 היסטוריה (`suggestItems`) | `🎒 מטען · לקחת אותו ב-4 מתוך 5 יציאות קודמות` |
| 🌦️ מזג אוויר (`departureTips`) | `☔ מטרייה · 🌧️ צפוי גשם — 70% סיכוי` · `💧 בקבוק מים · ☀️ צפוי להיות חם — 32°` · `🧣 מעיל · ❄️ צפוי קר — 10°` |
| 🧠 המשפט שנכתב (מסך התוכנית בלבד) | `🧺 מגבת · לפי מה שכתבת` |

לכל שורה כפתור **➕ הוסף** משלה, שמוסיף אותה בלבד דרך `addSuggestedItems` הקיים.
**שום דבר לא מתווסף לבד.** פריט שכבר ברשימה לא מוצע (השוואה לפי שם מנורמל, ולפי
מילים נרדפות בהצעות מזג האוויר — "בקבוק מים" מכסה "מים"), ואותו דבר לא מוצע פעמיים
משני מקורות. אין הצעות → הכרטיס לא מצויר בכלל.

ההצעות של מזג האוויר יושבות כאן ולא בכרטיס מזג האוויר, כדי שלא יופיעו פעמיים.
אין אימוג'י פר‑פריט בהיסטוריה (האפליקציה לא שומרת כזה, וניחוש לפי שם הוא נתון
מומצא) — לכן שורות היסטוריה מקבלות 🎒 נייטרלי, ושורות מזג אוויר את האימוג'י של
התנאי עצמו.

#### הבסיס: `src/suggestions.ts`

פונקציה טהורה, בלי AI, בלי שרת, בלי נתוני דמו. הכול מחושב מהיציאות שנשמרו
באפליקציה.

הכללים:

| כלל | מימוש |
| --- | --- |
| רק אותו יעד | סינון לפי `destinationId` |
| לפחות 3 יציאות | `MIN_TRIPS_FOR_SUGGESTIONS`, נספרות רק יציאות עם פירוט פריטים |
| "פריט נפוץ" | נלקח ברוב היציאות: `takenIn * 2 > tripsAnalysed` (בדיוק חצי לא נחשב) |
| לא להציע מה שכבר ברשימה | מסונן מול הפריטים ה**פעילים** של היעד |

פריטים מושווים לפי שם מנורמל (`normalizeItemName`) ולא לפי `id`, כי שורה שנמחקה
ושורה שהוקלדה מחדש הן אותו דבר מבחינת המשתמש.

**למה בכלל יש מה להציע:** פריט מוצע רק אם הוא לא ברשימה כרגע — כלומר בדרך כלל
פריט ש**הוסר** מהיעד. לכן `הוסף הכול` לא יוצר שורה חדשה אלא **מחזיר לפעילות** את
השורה הקיימת (`addSuggestedItems` ב‑store); שם חדש לגמרי נוסף כשורה חדשה. כך אין
כפילויות בשום מסלול.

ההצעות הן המלצה בלבד — הרשימה לא משתנה עד שהמשתמש לוחץ.

בכרטיס אין אימוג'י לכל פריט, כי האפליקציה לא שומרת אימוג'י לפריטים וניחוש לפי שם
היה נתון מומצא. במקומו מוצגת התדירות האמיתית (`3/4 יציאות`).

### 🔔 תזכורות יציאה

מתג ראשי ב‑הגדרות (`settings.notifications`) + תזכורת לכל יעד
(`destination.reminder`: `enabled`, `time`, `days[]`). כשהמתג כבוי לא נשלחת שום
התראה. הרשאות: מבוקשות רק בלחיצה מפורשת; במצב `denied` מוצג
"⚠️ ההתראות חסומות בדפדפן" עם הוראות במקום שגיאה טכנית.

`useReminders` בודק כל 20 שניות (מדויק יותר מטיימרים ארוכים שנסחפים כשהמכשיר
נרדם), עם שמירה מפני שליחה כפולה לאותה דקה. לחיצה על ההתראה נתפסת ב‑`sw.js`
(`notificationclick`) ופותחת/ממקדת את האפליקציה ב‑`/destination/<id>/check`.

**מגבלה אמיתית:** תזכורת מקומית נשלחת רק כשהאפליקציה פתוחה. שליחה ברקע דורשת
Web Push (שרת) או בילד נייטיב עם expo-notifications — `NotificationChannel` הוא
נקודת החיבור לשם.

### 🚌 תחבורה ציבורית

`destination.travelMode` (`car`/`bus`/`walk`/`bike`) ו‑`destination.transit`
(תחנת מוצא, תחנת יעד, שעת הגעה רצויה) — הכול נשמר עם היעד.

שכבת הנתונים מופרדת לגמרי מהממשק:

```
src/transit/provider.ts   ← TransitProvider: getNearbyStops / searchStops /
                             getTransitOptions / getRealtimeTransitData
src/transit/strideProvider.ts ← מימוש מול GTFS הרשמי
src/transit/index.ts      ← export const transit = strideProvider
```

מסכים מייבאים `transit` בלבד, אז החלפת מקור נתונים היא שורה אחת ב‑`index.ts`.

**מקור הנתונים:** לוח הזמנים הרשמי של משרד התחבורה (GTFS), דרך open-bus Stride
של הסדנא. **בלי API key ובלי backend** — ה‑API מחזיר `Access-Control-Allow-Origin: *`,
כך שאין שום secret באפליקציה. כל מספר קו, תחנה וזמן מגיע מהפיד.

איך תוכנן סביב מגבלות ה‑API:
- אין סינון גאוגרפי או חיפוש לפי שם בצד השרת, לכן רשימת התחנות (~30k) נטענת
  **פעם אחת, רק כשהמשתמש מבקש** תחנות, ונשמרת בזיכרון הסשן בלבד — לא בדיסק,
  כדי שלא תדחוק את הנתונים של המשתמש.
- מזהה תחנה תקף ליום לוח זמנים אחד, לכן נשמר `code` היציב והמזהה נפתר מחדש
  לפי תאריך (עם נפילה אחורה עד 4 ימים כשהאינג'סט מתעכב).
- ה‑API מתעלם מפילטר הזמן ב‑SIRI, לכן טריות נתוני זמן אמת נאכפת בקוד (10 דקות);
  מידע ישן לא מוצג כ"בזמן אמת".

מיקום מבוקש רק בלחיצה על "📍 מצא תחנות קרובות אליי".

#### התחנה נמצאת לבד — לא נבחרת ביד

המשתמש לא בוחר תחנת מוצא. כשהיציאה היא באוטובוס, `nearbyRoute.ts` עושה את זה:

```
מיקום המשתמש (בהרשאה) → getNearbyStops → 5 תחנות מועמדות
        ↓  לכל מועמדת, במקביל: getTransitOptions ליעד
התחנה הקרובה ביותר שממנה יש נסיעה אמיתית  ← זו התשובה
```

**הכלל שחשוב:** לא התחנה הגיאוגרפית הקרובה, אלא **הקרובה ביותר שיש ממנה נסיעה
ליעד**. תחנה במרחק 0 מ׳ בלי קו ליעד נדחית לטובת אחת במרחק 150 מ׳ שיש ממנה קו —
זה נבדק בפועל מול הפיד האמיתי.

**היעד:** תחנת יעד ששמורה על היעד עדיפה; אחרת התחנות הקרובות לקואורדינטות של היעד
(מהכתובת שעברה geocoding, או מ"📍 בחר מיקום"). אין ליעד מיקום → נאמר במפורש, בלי
לנחש נקודה.

**מה מוצג:** התחנה, למה היא (מרחק בקו אווירי + הערכת דקות הליכה), הקו, "יוצא בעוד
N דק׳", תחנת הירידה, הגעה משוערת לפי לוח הזמנים, ומצב זמן אמת כשהפיד מדווח משהו —
אחרת נאמר שאין ונשארים על לוח הזמנים. נסיעות נוספות מאותה תחנה מוצגות רק אם הן
עוד לא יצאו.

**הרשאת מיקום:** מבוקשת רק כשהיציאה באוטובוס. סירוב → הודעה + "נסה שוב" +
"📍 בחר תחנה"; אם ליעד יש תחנת מוצא שמורה מהעבר, היא משמשת כמסלול חלופי ומסומנת
כ"התחנה ששמורה ליעד".

**בחירה ידנית:** "📍 בחירת תחנה אחרת" פותח את בורר התחנות הקיים; הבחירה נשמרת
ב‑`DepartureStops` בזיכרון — **ליציאה הנוכחית בלבד**, בלי לגעת בהגדרות היעד — ויש
"↩︎ חזרה לתחנה שנמצאת אוטומטית". תחנה שנבחרה ואין ממנה נסיעה אומרת את זה עליה, לא
על הסביבה.

**ביצועים:** תוצאה נשמרת 5 דקות למפתח של (יעד, מיקום מעוגל ל‑~100 מ׳, חלון הגעה של
10 דקות), קריאות מקבילות מתמזגות לחיפוש אחד, והחיפוש רץ רק כשהמסך פתוח במצב אוטובוס
— לא כל כמה שניות. חיפוש אחד = עד 5 בדיקות לוח זמנים במקביל, ותחנת יעד שנייה נבדקת
רק אם הראשונה לא הניבה כלום.

**מה לא שונה:** ה‑provider עצמו (`strideProvider`) לא נגעתי בו — הכול נבנה מעל
`getNearbyStops` / `getTransitOptions` / `getRealtimeTransitData` הקיימים.
כרטיס `MyRouteCard` הישן, שדרש תחנת מוצא שמורה, נמחק כי `BusRouteCard` החליף אותו
בשני המסכים.

#### זמן אמת

הכרטיס "🚌 הדרך שלי" מציג את הסטטוס החי של **הנסיעה הבאה** (האפשרות הראשונה),
דרך `getRealtimeTransitData` הקיים.

**מה המקור באמת נותן:** מיקומי רכבים (SIRI) — איפה האוטובוס ומתי הדיווח נרשם.
**אין בו תחזית הגעה ואין בו סטייה מלוח הזמנים.** לכן מוצגים רק דברים נמדדים:
נוכחות חיה, גיל הדיווח (🟢 עד 3 דקות, 🟡 עד 10), מספר הרכבים המדווחים בקו,
ומרחק בקו אווירי מהרכב הקרוב לתחנת העלייה. הזמנים עצמם נשארים של לוח הזמנים,
והכרטיס אומר זאת במפורש. **לא מחושב זמן הגעה ולא מוצגת הודעת עיכוב** — אין נתון
שמאפשר את זה בכנות.

**זהות הקו — הבאג שתוקן בדרך.** דיווחי הזמן אמת ממופתחים לפי `line_ref` של הפיד,
לא לפי המספר הכתוב על האוטובוס: לאותו "קו 2" של אותו מפעיל יש `line_ref` שונה
במודיעין עילית, בשוהם ובביתר עילית. הקוד הקודם שלח את המספר המפורסם בפרמטר
`siri_routes__line_refs` — שם שה‑API בכלל לא מכיר, ופילטר לא מוכר נזרק בשקט, כך
שחזרו רכבים של קווים אחרים לגמרי. עכשיו:
- `TransitOption` נושא `lineRef` / `operatorRef` (הם ממילא היו בשורות שהלוח מביא),
- הבקשה משתמשת ב‑`siri_routes__line_ref` (יחיד) יחד עם `siri_routes__operator_ref`,
- וכל שורה שחוזרת נבדקת בקוד מול ה‑`lineRef` המבוקש — אותו היגיון שכבר נהוג שם
  לגבי הטריות, כי המקור לא מכבד פילטרים.
- בלי `lineRef` הפונקציה מחזירה "אין מזהה קו לבדיקת זמן אמת" ולא שולחת בקשה בכלל.

**רענון:** בקשה אחת כשהכרטיס נפתח, ואז כל 60 שניות בזמן שהוא פתוח. `🔄 רענן`
כפוף למגבלת קצב משותפת של 20 שניות לכל קו — הכפתור מושבת ומראה ספירה לאחור,
ותוצאה בתוך החלון מוגשת מהזיכרון. אין שום polling ברקע: כשהמסך נסגר הבקשות נעצרות.

**הכנה להתראות:** `summarizeRealtime` היא פונקציה טהורה שמחזירה גם
`minutesToScheduledDeparture` לצד הנוכחות והטריות — בדיוק הקלט שדרוש כדי להחליט
בעתיד "🔔 הגיע הזמן לצאת". מנגנון ההתראות עצמו לא נגענו בו.

### 🌦️ מזג אוויר

תחזית אמיתית לשעה שבה המשתמש באמת יהיה בחוץ — כרטיס אחד במסך בדיקת היציאה, ועוד
אחד בתוכנית היציאה (שם לפי השעה שנאמרה במשפט).

```
src/weather/types.ts            ← WeatherProvider + WeatherReading + WeatherResult
src/weather/openMeteoProvider.ts ← מימוש מול Open-Meteo (geocoding + forecast)

src/weather/cache.ts            ← cache מתמשך + מיזוג בקשות מקבילות

                                  + getDestinationWeather (נקודת הכניסה היחידה)
src/weather/useWeather.ts       ← useDepartureWeather: תחזית + הצעות למסך
src/departureContext.ts         ← יעד + רשימה + היסטוריה + מזג אוויר, ומהם ההצעות
```

`Access-Control-Allow-Origin: *` — אותו שיקול כמו במקור התחבורה. הרישיון CC-BY 4.0,
ולכן המקור מוצג בכרטיס עצמו וגם ב"מקורות המידע" שבהגדרות.

**איך נמצא המיקום.** קואורדינטות ששמורות על היעד (`coords`) עדיפות, ואחרת הכתובת
עוברת geocoding — **פעם אחת**: תוצאה מוצלחת נשמרת על היעד יחד עם `coordsLabel`,
השם שהותאם בפועל, כך שהחיפוש לא חוזר וגם התחזית ממשיכה לומר לאיזה מקום היא. ה‑API הזה מזהה שמות מקומות ולא
מספרי בתים: `"הרצל 10, תל אביב"` במלואו לא נמצא בכלל, וההתאמה המקורבת שלו אף החזירה
**"הרצליה"** — עיר אחרת. לכן הכתובת נקראת כפי שהיא נכתבת: **החלק האחרון אחרי הפסיק
הוא העיר, והוא נבדק ראשון**, אחר כך החלקים שלפניו, ורק בסוף הכתובת כמכלול. השם שהותאם
מוצג למשתמש (`תל אביב-יפו, ישראל`), כך שתחזית ברמת עיר לא מוצגת כאילו היא ברמת רחוב.
בלי כתובת, או כשאין התאמה, הכרטיס אומר **"⚠️ לא הצלחנו למצוא את מיקום היעד"** ומציע
**"📍 בחר מיקום"** — סרגל עם שתי אפשרויות אמיתיות: לקבוע את המיקום לפי המקום שהמשתמש
נמצא בו כרגע (אותה יכולת שכבר משמשת את "מצא תחנות קרובות אליי", ונשמרת בשם
"המיקום שבחרת"), או לחזור לתקן את הכתובת. **לא נבנתה שכבת מפות**, ובוחר נקודה על מפה
ייכנס כאפשרות שלישית באותו סרגל. עד שיש מיקום — אין תחזית, ולא מוצג שום נתון מומצא.

**איזו שעה.** יעד עם "להגיע עד" (הגדרת האוטובוס) מקבל תחזית לשעת ההגעה; כל השאר
מקבלים את השעה הנוכחית. שעת הגעה שכבר חלפה נחשבת ל"עכשיו".

**מה מוצג:** טמפרטורה, תחושת טמפרטורה, מצב בעברית + אימוג'י, סיכוי לגשם, כמות משקעים
(רק כשהיא גדולה מאפס) ורוח עם משבים. שדה שהמקור לא החזיר פשוט לא מקבל שורה, ואף פעם
לא מוצג קוד מספרי.

**הצעות:** `departureTips` מחזיר הצעה רק כשהנתון מצדיק אותה — ☔ מטרייה מ‑50% סיכוי
לגשם (או משקעים בפועל, או קוד גשם), 💧 בקבוק מים מ‑28°, 🧥 מעיל מרוח 30 קמ"ש (או
משבים 45), 🧣 מעיל/שכבה כשהתחושה יורדת ל‑12° ומטה. כל הצעה נושאת את המספר שהצדיק
אותה, והן מוצגות בכרטיס **🧠 כדאי לבדוק** יחד עם ההצעות מההיסטוריה — לא בכרטיס מזג
האוויר, כדי שלא יופיעו פעמיים.

**שילוב עם AI בעתיד:** `buildDepartureContext` מרכיב אובייקט אחד עם היעד, הרשימה,
מה שההיסטוריה אומרת ומזג האוויר — בדיוק מה שעוזר אמיתי יקבל. `checkSuggestions`
הוא הצרכן היחיד שלו, כך שחיבור מודל בעתיד מחליף פונקציה אחת (ב‑`analyzeUserText`)
במקום להיפרס על המסכים. **שום מודל לא מחובר.**

**Cache:** `dont-forget:weather:v1`. תחזית טרייה 30 דקות, geocoding 30 יום (והחמצה
6 שעות, כדי לא לתקוף את ה‑API על כתובת שגויה). בקשות מקבילות לאותו מיקום מתמזגות
לבקשה אחת, ולכן שני הכרטיסים יחד עולים round trip אחד. טעינה מחדש בתוך חלון הטריות
לא שולחת בקשה בכלל.

**שגיאות:** אין אינטרנט → "לא ניתן לקבל כרגע את נתוני מזג האוויר"; שגיאת שירות →
הודעה ידידותית + "נסה שוב". בשני המצבים כל שאר האפליקציה ממשיכה לעבוד, ולא מוצג
שום נתון מומצא.

### 🧠 תוכנית יציאה חכמה

משפט אחד באזור ה‑AI — מוקלד או מדובר — הופך לסיכום אחד של כל מה שהאפליקציה כבר
יודעת על היציאה הזאת. **אין כאן מודל חדש ואין שירות חיצוני:** אותו `analyzeUserText`
מקומי, אותן שכבות מזג אוויר ותחבורה, אותו `startExit`.

```
משפט → analyzeUserText (מקומי)      → איזה יעד
     → parseTimePhrase  (מקומי)      → איזו שעה
     → יעד קיים?  כן → /plan
                  לא → הגלגל הקיים (AiSuggestionSheet) → יצירה באישור → /plan
```

**מה יש בתוכנית:** 📍 היעד · ⏰ הזמן שזוהה · 🎒 הרשימה הקיימת + המלצות · 🌦️ מזג אוויר
**לשעה המתוכננת** · 🚌 הדרך (לוח זמנים + זמן אמת, מכוונים לשעה המתוכננת) · 🗺️ ניווט ·
🔔 תזכורת · ובתחתית **🚀 התחל יציאה / ✏️ ערוך / ❌ ביטול**.

**זמן — `src/timePhrase.ts`.** parser מקומי קטן ומפורש: "עוד שעה", "בעוד 20 דקות",
"עוד חצי שעה", "מחר ב-8", "היום ב-19:30", "בערב", "עכשיו". שעה שנקבעה במפורש היא
`exact`; חלק מהיום ("בערב") הוא `approx` ומוצג עם השעה שממנה נגזר — `בערב (19:00)` —
כדי שהפרשנות תהיה גלויה ולא מוסתרת. **מה שלא הובן בוודאות מחזיר null**, והתוכנית
אומרת "לא זיהינו זמן במשפט" במקום לנחש. ("מחר" לבד הוא null בכוונה: יום בלי שעה
הוא לא זמן יציאה.)

שתי הערות מימוש שחסכו באגים אמיתיים:
- `` של JavaScript לא עובד ליד אותיות עבריות (הן לא "word characters"), ולכן גבולות
  מילה בקובץ הזה כתובים במפורש — רווח, סוף מחרוזת או פיסוק.
- זמן היעד לתחזית מקובע פעם אחת בפתיחת המסך; `Date.now()` בכל רנדר היה מפעיל את
  הבקשה מחדש בכל רנדר.

**המלצות לרשימה** מגיעות משני מקורות אמיתיים: מה שההיסטוריה אומרת שאתה בדרך כלל לוקח
ליעד הזה (`suggestItems`), ומה שהמשפט עצמו מרמז (`analyzeUserText`). מה שכבר ברשימה
לא מוצע שוב, **וכלום לא מתווסף בלי לחיצה**.

**יעד שלא קיים** לא נוצר לבד: המשפט מגיע ל‑`AiSuggestionSheet` הקיים, שם כתוב
"לא מצאתי יעד בשם הזה. ליצור יעד חדש?" — והיצירה קורית רק בלחיצת המשתמש, ואז נפתחת
התוכנית ליעד החדש.

**"🚀 התחל יציאה"** קורא ל‑`startExit` הקיים ומעביר למסך בדיקת היציאה, שם היציאה
מתבצעת. לא נבנתה שום מערכת יציאה חדשה.

### PWA

| קובץ | תפקיד |
| --- | --- |
| `public/index.html` | תבנית ה‑HTML: manifest, theme-color, תגי iOS, viewport, רישום ה‑SW |
| `public/manifest.json` | שם, שם קצר, `display: standalone`, צבעים, אייקונים |
| `public/sw.js` | Service Worker |
| `public/icons/*` | 192 / 512 / maskable-512 / apple-touch-icon / favicon |

כל מה שב‑`public/` מועתק כמו שהוא ל‑`dist/` בזמן `expo export`.

**עדכונים בלי התקנה מחדש.** ניווטים ב‑SW הם network-first, ה‑SW קורא
`skipWaiting()` + `clients.claim()`, והדף מבקש מ‑worker חדש להשתלט מיד ואז מרענן
פעם אחת. בנוסף `registration.update()` נקרא בכל פעם שהאפליקציה חוזרת לחזית.

**נתוני משתמש לא נמחקים בעדכון.** הנתונים יושבים ב‑localStorage (דרך
AsyncStorage) ו‑`sw.js` לא נוגע בהם בכלל. ניקוי ה‑caches מוחק **רק** caches
שמתחילים ב‑`dont-forget-` וששמם אינו הגרסה הנוכחית — לא `caches.keys()` גורף.
בנוסף הדף מבקש `navigator.storage.persist()` כדי להוציא את האחסון מברירת המחדל
של פינוי אוטומטי.

לאלץ רענון cache בעתיד: להעלות את `v1` בשורת `CACHE` ב‑`public/sw.js`.

### מחשב וטלפון

`Screen` עוטף כל מסך בעמודה ממורכזת ברוחב מקסימלי של `contentMaxWidth` (520px).
בטלפון המסך צר מזה ולכן אין שום שינוי; בדפדפן על מסך רחב האפליקציה נשארת עמודה
ממורכזת בפרופורציות של טלפון במקום כרטיסים נמתחים לרוחב החלון.

### RTL

הממשק כולו עברית. במקום `I18nManager.forceRTL` (שדורש הפעלה מחדש ומתנהג
שונה בין פלטפורמות) כל שורה מוגדרת מפורשות כ‑`row-reverse` וכל טקסט כ‑
`textAlign: 'right'` — התוצאה זהה ב‑iOS, Android ובדפדפן.

## מה לא נכנס בכוונה

אין מודל AI, Bluetooth, מצלמה, פרסומות, משתמשים או תשלומים — רק MVP עובד.
מיקום המכשיר מבוקש רק בלחיצה מפורשת על "מצא תחנות קרובות אליי"; מזג האוויר
נשען על הכתובת של היעד ולא על מיקום המשתמש.
